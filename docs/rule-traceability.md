# Rule traceability

Requirement → database mechanism → test → report. Rule texts are those of plan §3; IDs are permanent. **This
document is checked against the database by `tests/test_rule_traceability.py`.** It checks that:

- every `brNN_…` constraint, index and trigger in the catalog, and every name a trigger raises, appears here;
- every name an error can carry is asserted by a test;
- every rule has an assertion in `tests/test_business_rules.py`;
- every rule has its own row;
- nothing here names an object the database doesn't have.

A violation reaches the API as 409 with the name as its `code` (`app/errors.py`). "Week 10" follows plan T-8:
*beyond* marks the optional features beyond Week 10, and *unresolved* the statement-level `TRUNCATE` triggers T-8
still has to place. Test references are `file::function` under `tests/`; the `test_business_rules.py` one comes
first.
